Mailbox Lead Generation

A decantation inbox for your incoming email: every message is classified, optionally triaged by AI, matched against your catalog and converted into clean CRM leads.

Developed by vicbas.com

What it does

Pre-stage inbox

Emails fetched from your mail server land as Mailbox records instead of going straight to sales — nothing reaches the pipeline unreviewed.

Classification by destination

Inquiry addresses (buyers) and acquisition addresses (suppliers) are classified by arrival address, so each type follows its own flow.

Optional AI triage

Any OpenAI-compatible endpoint summarizes, categorizes and extracts contact data; records are matched against your product catalog for suggestions. Leave the key empty and the module works fully without AI.

How to use it

From install to first converted lead:

  1. Install the module
    Standard Community dependencies (crm). The python requests library is required for the optional AI triage.
  2. Configure the classification addresses
    Settings → Mailbox Lead Generation: list the inquiry addresses and the acquisition addresses (comma separated). Everything else can stay on defaults.
  3. Point fetchmail at the mailbox
    Create an Incoming Mail Server whose server action creates records of model mailbox.lead.generation (the module's help shows the exact setup).
  4. Optional: connect an AI provider
    In the same settings: base URL, API key, model, temperature, retries. Empty key = AI disabled. A cron (every 5 minutes) processes the pending queue.
  5. Review and convert
    Open the Mailbox menu: read the email with its classification, review the AI summary and catalog suggestions, then Convert to Lead. Spam is rejected with one click.

Key features

Feature Detail
Product matching Catalog keywords from the email body are matched against your product catalog (any product type) and offered as suggestions on the record.
Spam rejection One click rejects an email before it ever touches the pipeline.
Full traceability The original message, classification, AI output and suggestions stay attached to the record.
Provider-agnostic AI OpenAI, Azure OpenAI, local vLLM/Ollama — any OpenAI-compatible endpoint works.
Multilingual UI English + Spanish (es, es_CL) translations included.

Requirements
